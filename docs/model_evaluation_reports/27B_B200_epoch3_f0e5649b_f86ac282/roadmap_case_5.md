## 프로젝트와 조건

- 목표: 기존 검색 코드에 근거 누락 검출과 회귀 시험 추가
- 관점: 업무 적용 우선
- 기간: 5주 · 주당 4시간 · 예산 0원

## 계획

검증 우선: 근거 누락 검출·회귀 시험 추가(1주, 4시간)

기존 문서 분할·검색 코드가 이미 존재하므로 기초 재학습은 배제하고, 누락된 근거(문서·패스)를 자동으로 탐지하는 검증 모듈과 회귀 테스트를 추가해 검색 결과의 신뢰성을 높이는 데 집중합니다. 총 1주(4시간) 안에 구현·검증 가능한 최소 기능(MVP)을 만들고, 실패 사례(누락된 근거)를 재현하는 회귀 테스트를 포함합니다.

### 1. 검증 요구사항 정의 및 테스트 케이스 설계

- 목표: 누락 검출의 기준(예: 기대 문서 ID/패스 목록)과 회귀 테스트 시나리오를 명확히 정의
- 기간: 0.5 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 기존 검색 파이프라인의 입력·출력 포맷 확인(문서 ID, 메타데이터, 스코어 등)
- 활동: 누락 판정 기준 정의: 기대 근거 목록(문서 ID 또는 경로)과 허용 오차(예: Top-K 범위) 설정
- 활동: 대표 누락 사례 3~5개 선정(실제 쿼리·기대 문서 포함)
- 산출물: 검증 요구사항 문서(누락 판정 기준, 허용 오차, 테스트 케이스 목록)
- 산출물: 테스트 케이스 파일(쿼리, 기대 문서 ID/패스, 기대 결과 설명)
- 완료 기준: 미확인

### 2. 검증 모듈 구현 및 회귀 테스트 작성

- 목표: 검색 결과와 기대 근거를 비교해 누락을 탐지하는 함수 구현 및 자동화된 회귀 테스트 추가
- 기간: 0.375 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 검색 결과 포맷을 파싱해 기대 문서 ID/패스와 매칭하는 검증 함수 구현
- 활동: 누락 탐지 로직(예: 기대 문서가 Top-K에 포함되지 않으면 누락으로 판정) 구현
- 활동: 테스트 케이스를 자동 실행하는 회귀 테스트 스크립트 작성(예: pytest 또는 간단한 스크립트)
- 산출물: 검증 모듈 코드(예: verify_results.py) — 입력: 검색 결과, 기대 문서 목록; 출력: 누락 여부 및 누락된 문서 목록
- 산출물: 회귀 테스트 스크립트(테스트 케이스를 순회하며 실패 시 로그/리포트 생성)
- 완료 기준: 미확인

### 3. 검증 실행·결과 분석 및 개선 제안

- 목표: 회귀 테스트 실행으로 누락 사례를 재현하고, 원인(예: 토큰화·임베딩·정렬 문제)을 간단히 분석해 개선 우선순위를 제시
- 기간: 0.125 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 회귀 테스트 실행 및 실패 사례 수집
- 활동: 누락 사례에 대해 간단한 원인 분석(예: 토큰화 차이, 임베딩 유사도 문제, 메타데이터 불일치)
- 활동: 개선 우선순위(단기 패치 vs 장기 재학습)를 1페이지 요약으로 작성
- 산출물: 회귀 테스트 실행 결과 리포트(누락된 쿼리·문서 목록, 실패 로그)
- 산출물: 원인 분석 요약 및 개선 제안(우선순위 포함)
- 완료 기준: 미확인
