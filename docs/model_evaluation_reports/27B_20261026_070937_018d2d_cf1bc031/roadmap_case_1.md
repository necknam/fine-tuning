- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

2주 실습 집중: 공유 카운터 레이스 재현 및 잠금 적용 비교

제한된 시간(2주, 총 6시간)과 예산(0원)을 고려해 목표 범위를 최소화하여 로컬에서 재현 가능한 동시성 버그(스레드 두 개가 공유 카운터를 증가시킬 때 발생하는 레이스 컨디션)를 만들고, mutex 적용 전후의 로그를 비교해 차이를 문서화한다. 이론 학습은 최소한으로 병행하여 실습·검증에 중점 둔다.

### 1. 환경 준비 및 레이스 재현

- 목표: 로컬에서 재현 가능한 최소 예제(스레드 2개, 공유 카운터)를 작성하고 레이스가 발생하는 로그를 확보한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 개발 언어 선택(권장: C 또는 Python). 비용·시간 고려: C는 컴파일 필요, Python은 빠른 실행·설치 용이.
- 활동: 로컬 개발 환경 확인(컴파일러/인터프리터, 빌드 도구).
- 활동: 작은 연습 문제 설계: 두 스레드가 전역(또는 공유) 정수 카운터를 100,000번씩 증가시키는 프로그램 작성(동기화 없음).
- 활동: 프로그램을 여러 번 실행해 최종 카운터 값이 기대값(200,000)과 다른 경우(증분 손실)를 로그로 수집.
- 활동: 간단한 실행 스크립트로 반복 실행 및 결과 수집(예: 10회 반복, 각 실행의 최종값 기록).
- 산출물: 소스코드(예: race_condition.c 또는 race_condition.py)
- 산출물: 실행 스크립트(반복 실행용) 및 수집된 로그(예: 10회 실행 결과 CSV)
- 산출물: 짧은 실행 가이드(README, 1페이지)
- 완료 기준: 미확인

### 2. 동기화 적용·비교·문서화

- 목표: mutex 또는 동등한 동기화 기법을 적용해 레이스를 제거하고, 적용 전후 로그를 비교하여 차이를 정량·정성적으로 설명한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 동기화 적용: 선택한 언어에 맞는 mutex(예: pthread_mutex_t 또는 Python의 threading.Lock)를 적용하여 동일 작업을 수행.
- 활동: 동기화 적용 전/후 각각 동일한 반복 실행(예: 10회)을 수행해 로그 수집.
- 활동: 결과 비교: 최종 카운터 값의 분산·오류 발생 빈도 비교, 실행 시간(대략적 오버헤드) 측정.
- 활동: 결과 요약 문서 작성: 재현 방법, 로그 비교 표, 원인(원자성 부족)과 해결(뮤텍스) 설명, 한계(플랫폼·언어별 차이, 성능 오버헤드) 기술.
- 산출물: 수정된 소스코드(뮤텍스 적용 버전)
- 산출물: 비교 로그(전/후) 및 간단한 비교표(CSV 또는 마크다운 표)
- 산출물: 결과 요약 문서(최대 2페이지): 재현 절차, 비교 결과, 해석, 한계
- 완료 기준: 미확인
