# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

2주(총 6시간) — 로컬 스레드 경합 재현 및 잠금 적용 비교 실험

가용 시간(2주, 주 3시간, 총 6시간)과 예산(0원)을 우선 반영해 목표 범위를 '로컬에서 스레드 두 개가 공유 카운터를 동시에 증가시킬 때 발생하는 경합(race condition)을 재현하고, mutex 적용 전후의 로그를 비교해 차이를 정량·정성적으로 분석'으로 축소했습니다. 외부 유료 서비스나 추가 인원은 사용하지 않으며, 모든 활동은 로컬 환경에서 수행 가능한 최소 실험으로 구성합니다. 시작점(start_stage=2)을 고려해 기초 개념 반복 학습은 배제하고, 재현·측정·비교에 집중합니다.

### 1. 경합 재현 및 기준선 수집

- 목표: 간단한 멀티스레드 프로그램을 작성해 경합을 재현하고, 잠금 미적용 상태의 로그를 수집해 기준선(baseline)을 만든다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 개발환경 준비: C/C++ 컴파일러(gcc/clang) 또는 Python(venv) 설치 확인(로컬, 비용 없음).
- 활동: 작업용 소스 작성: 두 개의 스레드가 공유 카운터를 N회(예: 각 스레드 1,000,000회) 증가시키는 최소 프로그램 작성(예: C에서 pthread 사용 또는 Python의 threading 사용).
- 활동: 실행 스크립트 작성: 동일 조건에서 프로그램을 10~20회 반복 실행해 로그(최종 카운터 값, 실행 시간)를 수집하는 간단한 셸 스크립트 작성.
- 활동: 결과 기록: 각 실행의 최종 카운터 값과 예상값(예: 2,000,000)과의 차이를 표로 정리.
- 산출물: 소스 코드(예: race_counter.c 또는 race_counter.py) — 잠금 미적용 버전
- 산출물: 실행 스크립트(반복 실행용) 및 수집된 로그 파일(예: baseline_logs.txt)
- 산출물: 간단한 결과 요약(최종 카운터 분포, 평균·최소·최대, 예상값과의 차이)
- 완료 기준: 미확인

### 2. 잠금 적용 및 비교 분석

- 목표: mutex(또는 동등한 동기화 기법)를 적용해 재현 실험을 반복하고, 잠금 적용 전후의 로그를 비교해 차이를 정량·정성적으로 분석한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 동기화 적용: mutex(예: pthread_mutex_t) 또는 언어별 동기화(예: Python의 threading.Lock)를 적용한 버전 작성.
- 활동: 동일 조건 반복 실행: Phase 1과 동일한 반복 횟수로 실행해 로그 수집(예: locked_logs.txt).
- 활동: 비교 분석: baseline과 locked 로그를 비교해 최종 카운터의 일치 여부, 실행 시간 변화(오버헤드), 재현성(불일치 빈도)을 표로 정리.
- 활동: 결과 문서화: 1페이지 분량의 비교 요약(방법, 수치, 해석, 한계) 작성.
- 산출물: 소스 코드(예: race_counter_locked.c 또는 race_counter_locked.py) — 잠금 적용 버전
- 산출물: 비교 로그 파일(locked_logs.txt) 및 비교표(CSV 또는 마크다운 표)
- 산출물: 최종 비교 요약 문서(방법·결과·해석·한계 포함)
- 완료 기준: 미확인
