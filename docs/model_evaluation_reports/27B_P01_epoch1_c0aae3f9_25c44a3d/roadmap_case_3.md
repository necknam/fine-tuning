## 계획

업무 적용 우선: 최소 기능 RAG 시제품으로 근거 표시·근거 누락 구분 구현

2주(총 6시간) 동안 Python 기반 최소 RAG 시제품을 구현한다. 1주차는 데이터 준비와 검색 파이프라인 구성, 2주차는 RAG 파이프라인 구현과 5개 질문 실행·평가로 구성된다. 각 단계는 실제 업무 적용 관점(비용·시간·업무 적용)을 반영해 로컬·무료 도구 우선, 최소 기능 구현에 집중한다. 비용·시간이 확인되지 않은 자료는 무료·소요 시간으로 단정하지 않는다.

### 1. 데이터 준비 및 검색 파이프라인 구성

- 목표: 가상 규정 3건과 질문 5건을 준비하고, 문서 분할·임베딩·벡터 저장소(로컬)를 구성해 검색 결과를 원문 위치와 함께 반환할 수 있게 한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 가상 규정 3건(각 200자 내외)과 질문 5건(근거 있음 3건, 근거 없음 2건)을 작성
- 활동: 문서 분할 전략(문단/문장 단위) 결정 및 분할 코드 작성
- 활동: 임베딩 모델 선택(로컬 또는 API) 및 벡터 저장소(FAISS/Chroma 등) 구성
- 활동: 검색 함수 구현: 쿼리 입력 → 상위 k개 문서 조각 + 원문 위치 반환
- 산출물: 가상 규정 3건(각 200자 내외)과 질문 5건(근거 있음 3건, 근거 없음 2건)의 데이터 파일
- 산출물: 문서 분할·임베딩·벡터 저장소(로컬) 구성 코드
- 산출물: 검색 결과와 원문 위치를 함께 반환하는 검색 함수
- 완료 기준: 미확인

### 2. RAG 파이프라인 구현 및 기본 평가

- 목표: 검색 결과를 프롬프트에 안전하게 삽입해 LLM으로 답변을 생성하고, 답변에 근거(원문 위치)를 표시하거나 근거가 없음을 구분하는 로직을 구현한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 검색 결과를 프롬프트 템플릿에 삽입하는 코드 작성(컨텍스트 주입)
- 활동: LLM 호출(로컬 또는 API) 및 응답 파싱
- 활동: 응답 포맷 설계: 답변 + 근거(문서 ID·위치) 또는 '근거 없음' 표시
- 활동: 5개 질문으로 실행하고 결과 로그 수집
- 산출물: RAG 시제품 코드(검색→프롬프트→LLM 호출→응답 포맷)
- 산출물: 5개 질문에 대한 실행 로그(검색 결과, 프롬프트, LLM 응답, 근거 표시 여부)
- 산출물: 간단한 평가표(정답 여부, 근거 표시 여부, 근거 누락 여부)
