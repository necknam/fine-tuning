- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선

## 계획

비용 우선·짧은 주기 실습 중심 로드맵

가용 시간(총 2주, 주 3시간)과 예산(0원)을 고려해 로컬에서 직접 재현 가능한 최소 단위 실험을 수행한다. 목표는 복잡한 시스템 구현이 아니라 '재현 → 동기화 적용 → 로그 비교'의 작은 실험 루프를 완성해 동시성 문제의 원인과 잠금의 효과를 체감하는 것이다. 제공된 K-MOOC 강좌는 참고 자료로 연결하되, 예산·시간 제약 때문에 전체 강좌 이수 대신 관련 주차(프로세스/스레드, 동기화)의 핵심 개념만 선택적으로 참조한다.

### 1. 재현 및 기초 관찰

- 목표: 로컬 환경에서 스레드 두 개가 공유 카운터를 동시에 증가시킬 때 발생하는 경합(race condition)을 재현하고 로그로 기록한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 개발환경 준비(컴파일러/인터프리터, 간단한 편집기).
- 활동: 작은 재현 프로그램 작성: 두 스레드가 공유 카운터를 N번(예: 1,000,000) 증가시키는 코드 작성(잠금 없음).
- 활동: 프로그램을 여러 번 실행해 결과(최종 카운터 값)를 기록하고 비결정적 오류(예: 기대값과 다른 값)를 캡처.
- 활동: 실행 로그와 재현 절차를 README에 정리.
- 산출물: 간단한 재현 코드(예: C 또는 Python 스레드 기반) — 잠금 미적용 버전
- 산출물: 실행 스크립트(동일 환경에서 반복 실행을 위한 명령어 목록)
- 산출물: 실행 로그(최소 5회 반복 실행 결과)와 관찰된 오류 요약
- 완료 기준: 미확인

### 2. 동기화 적용 및 비교 분석

- 목표: 동기화(예: mutex, atomic, 또는 조건변수)를 적용해 재현된 오류를 제거하고 잠금 적용 전후의 로그를 비교·분석한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 잠금 적용: mutex 또는 atomic 연산으로 공유 카운터 접근을 보호하는 코드 수정.
- 활동: 동일한 반복 실행을 수행해 잠금 적용 전후의 결과 로그를 수집.
- 활동: 로그 비교: 오류 발생 빈도, 최종 카운터 값의 일관성, 실행 시간(대략적) 차이 기록.
- 활동: 결과를 바탕으로 동시성 문제의 원인(경합 발생 지점)과 잠금의 효과·한계를 1페이지 분량으로 정리.
- 산출물: 잠금 적용 버전 코드(예: mutex 또는 atomic 사용)
- 산출물: 잠금 전후 비교 로그(동일 반복 횟수)와 간단한 비교표
- 산출물: 짧은 분석 문서(문제 원인, 잠금의 효과, 성능·한계 설명)
- 완료 기준: 미확인
