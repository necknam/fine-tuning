# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

2주·주3시간으로 동시성 결함 재현→원인 격리→최소 수정 검증

총 2주(총 가용 학습시간 6시간) 동안 로컬 환경에서 스레드 간 공유 카운터의 경합(race condition)을 재현하고, 로그·반복 실행으로 오류를 확인한 뒤 최소한의 동기화(뮤텍스) 적용으로 문제를 해결해 전후 결과를 비교한다. 비용 우선 관점에서 외부 유료 자원 없이 로컬 도구(컴파일러, 간단한 스크립트)만 사용한다.

### 1. 환경 준비 및 결함 재현

- 목표: 로컬에서 재현 가능한 최소 예제(스레드 2개, 공유 카운터)를 작성하고 반복 실행으로 오류를 관찰한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 개발환경 준비: C 컴파일러(gcc/clang) 또는 Python(로컬 인터프리터) 선택 및 간단한 빌드/실행 스크립트 작성
- 활동: 최소 재현 코드 작성: 두 스레드가 같은 전역 카운터를 N번(예: 각 스레드 1,000,000회) 증가시키는 프로그램 구현
- 활동: 반복 실행 자동화: 10~50회 반복 실행 스크립트 작성(쉘/PowerShell)하여 결과 분산 관찰
- 활동: 로그 수집: 각 실행의 최종 카운터 값과 기대값(2*N) 차이 기록
- 산출물: 재현 코드(예: race_counter.c 또는 race_counter.py)와 빌드/실행 스크립트
- 산출물: 반복 실행 로그(예: 20회 실행 결과 CSV 또는 텍스트)
- 산출물: 간단한 관찰 보고서(오류 발생 빈도, 최대/최소/평균 최종 카운터 값)
- 완료 기준: 미확인

### 2. 원인 격리·최소 수정 적용 및 비교 검증

- 목표: 뮤텍스 등 최소 동기화 적용으로 오류가 해소되는지 확인하고, 잠금 전후 로그·통계를 비교하여 한계를 기술한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 원인 격리: 재현 코드의 경쟁 구간(비원자적 증가)을 주석·로그로 확인
- 활동: 최소 수정 적용: pthread_mutex_t(또는 언어별 락)로 증가 구간 보호
- 활동: 성능·정확성 비교: 잠금 적용 전후 동일한 반복 실행을 수행하여 정확성(오류 발생 여부)과 실행시간(대략적 오버헤드)을 기록
- 활동: 결과 정리: 잠금 전후 로그 비교표와 간단한 결론(수정 효과·한계·추가 개선 아이디어) 작성
- 산출물: 수정된 코드(뮤텍스 적용)와 빌드/실행 스크립트
- 산출물: 잠금 전후 비교 로그(정확성·실행시간 표)
- 산출물: 최소 1페이지 분량의 결론 보고서(원인, 수정 방법, 측정 결과, 한계)
- 완료 기준: 미확인
