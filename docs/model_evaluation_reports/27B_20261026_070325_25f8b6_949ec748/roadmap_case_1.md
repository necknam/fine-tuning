# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

비용 우선·짧은 기간의 실험적 재현 로드맵

주당 3시간, 총 2주(총 6시간) 안에 로컬 환경에서 스레드 간 공유 카운터의 동시성 오류를 재현하고, 잠금 적용 전후의 로그를 비교해 원인과 해결 효과를 문서화한다. 비용은 0원으로 제한하므로 로컬 도구와 무료 자료만 사용한다. 제공된 K-MOOC 강좌는 15주 분량으로 전체 수강은 불가능하므로 관련 주차(프로세스·스레드, 동기화)의 PDF·퀴즈만 선택적으로 참고한다.

### 1. 환경 준비 및 재현 코드 작성

- 목표: 로컬에서 재현 가능한 최소한의 동시성 오류 코드(스레드 2개, 공유 카운터)를 작성하고 실행해 오류를 확인한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 개발 환경 확인(예: Linux/macOS/WSL, C 또는 C++ 컴파일러, make 또는 간단한 빌드 스크립트).
- 활동: 간단한 프로그램 작성: 두 스레드가 공유 카운터를 N회 증가시키는 코드(잠금 미적용).
- 활동: 프로그램을 여러 번 실행해 최종 카운터 값이 기대값과 다른 경우(데이터 레이스)를 재현하고 로그(출력)를 수집.
- 활동: 재현 실패 시 스레드 수·반복 횟수·스케줄링 조건을 조정해 재현성 확보.
- 산출물: 소스 코드(예: race.c 또는 race.cpp)와 빌드 명령(README 포함).
- 산출물: 잠금 미적용 상태에서의 실행 로그(최소 5회 이상)와 재현 절차 문서.
- 산출물: 간단한 실행 스크립트(예: run_race.sh)로 재현 절차 자동화.
- 완료 기준: 미확인
- 추천 자료 KMOOC_21162: 제공 근거에서 확인되지 않음

### 2. 잠금 적용·비교·분석

- 목표: mutex(또는 동등한 동기화 기법) 적용 전후의 로그를 수집·비교하고, 결과의 차이를 정량·정성적으로 분석해 결론을 도출한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 동일한 코드에 mutex(또는 atomic) 적용 후 빌드 및 실행.
- 활동: 잠금 적용 전후의 실행 로그를 동일 조건에서 수집(각각 최소 5회 이상).
- 활동: 로그 비교: 최종 카운터 값 분포, 중간 상태(예: 중간 출력)의 차이, 실행 시간 변화 측정.
- 활동: 결과를 표·간단 그래프로 정리하고, 잠금의 효과와 한계(예: 성능 영향, 데드락 가능성)를 서술.
- 산출물: 잠금 적용 버전의 소스 코드(예: race_mutex.c)와 빌드 명령.
- 산출물: 잠금 적용 전후의 실행 로그(각각 최소 5회)와 비교표(최종 카운터 분포, 평균, 표준편차 등).
- 산출물: 최종 분석 보고서(최대 1~2페이지): 재현 방법, 로그 비교 결과, 잠금의 효과와 한계, 추가 실험 제안.
- 완료 기준: 미확인
