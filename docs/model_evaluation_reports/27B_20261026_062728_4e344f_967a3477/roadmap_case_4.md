# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 추가 외부 자료 없이 가상 문서 3건의 검색 실패를 재현하고 원인을 기록하기
- 관점: 비용 우선
- 기간: 10주 · 주당 2시간 · 예산 0원

## 계획

비용 우선의 실습 중심 2주 로드맵

주어진 제약(총 2주, 주 3시간, 예산 0원)을 반영해 실습 중심의 최소 산출물(다이어그램·장애 대응표)을 목표로 한다. 각 주에 3시간씩 총 6시간을 배정하여, 1주차에 단일 서버 아키텍처와 장애 시나리오를 문서화하고, 2주차에 이중화 아키텍처와 자동 복구 흐름을 다이어그램 및 대응표로 정리한다. 유료 서비스나 실제 배포는 하지 않으며, 산출물은 텍스트·이미지(다이어그램)와 표 형식의 문서로 제한한다.

### 1. 단일 서버 아키텍처 이해 및 문서화

- 목표: 단일 서버 아키텍처의 구성 요소와 장애 발생 시의 한계를 명확히 이해하고 문서화한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 단일 서버 아키텍처의 핵심 구성 요소(컴퓨팅, 스토리지, 네트워크, 모니터링)를 다이어그램으로 작성
- 활동: 단일 서버에서 발생할 수 있는 주요 장애 유형을 5개 이상 나열
- 활동: 각 장애 유형에 대해 수동 복구 절차와 한계를 표로 정리
- 산출물: 간단한 단일 서버 아키텍처 다이어그램(텍스트/이미지)
- 산출물: 단일 서버 장애 시나리오 목록(예: CPU 과부하, 디스크 장애, 네트워크 단절)과 각 시나리오에 대한 기본 대응 절차(수동 복구, 재시작, 로그 확인 등)
- 완료 기준: 미확인

### 2. 이중화 아키텍처 설계 및 장애 대응표 작성

- 목표: 이중화(레플리카, 로드밸런서, 다중 AZ 등) 아키텍처의 구성과 장애 시 자동 복구 흐름을 다이어그램과 대응표로 정리한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 이중화 아키텍처의 기본 패턴(예: 활성-스탠바이, 활성-활성, 로드밸런서 기반)을 다이어그램으로 작성
- 활동: 각 패턴에서 장애 발생 시 자동 복구 흐름(감지→격리→재배치/재시작)을 단계별로 기술
- 활동: 장애 대응표에 복구 시간(RTO), 데이터 손실 가능성(RPO), 운영 복잡도, 비용 영향 항목을 추가
- 산출물: 이중화 아키텍처 다이어그램(예: 로드밸런서 + 다중 인스턴스, 다중 AZ 구성 등)
- 산출물: 장애 대응표(장애 유형별 자동 복구 동작, RTO/RPO 추정, 수동 개입 필요 여부 포함)
- 산출물: 간단한 비교표: 단일 서버 vs 이중화(복구 시간, 운영 복잡도, 비용 영향)
- 완료 기준: 미확인
