## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 시간 우선
- 기간: 8주 · 주당 3시간 · 예산 20000원

## 계획

시간 우선: 최소 동작 RAG 시제품(근거 표시·분류 포함)

주당 3시간, 총 8주(총 24시간)로 최소 동작 RAG 시제품을 구현합니다. 목표는 가상 규정 3건(문서화)에서 질문 5건에 대해 근거를 표시하고, 근거가 없는 질문은 '근거 없음'으로 분류하는 것입니다. 이미 보유한 Python·데이터 처리 경험은 반복 학습하지 않고, LLM·RAG 기초와 실습 중심의 작은 구현에 집중합니다. 비용은 20,000원 이내로 유지하며, 유료 서비스는 사용하지 않습니다.

### 1. 1단계 · 준비 및 데이터 준비

- 목표: 가상 규정 3건(텍스트)과 질문 5건(근거 있음/없음 라벨 포함)을 준비하고, 평가 기준(정확성·근거 표시·분류 정확도)을 정의한다.
- 기간: 2 · 시간: 6시간 · 비용: 0원
- 활동: 가상 규정 3건(각 1~2페이지)을 텍스트로 작성(예: 인사규정·데이터관리규정·보안규정)
- 활동: 각 규정에 대해 5개 질문을 작성(근거 있음 3건, 근거 없음 2건) 및 라벨링
- 활동: 간단한 평가 체크리스트 작성(근거 표시 여부, 근거 위치, 분류 정확도)
- 산출물: 가상 규정 텍스트 파일 3개(.txt)
- 산출물: 질문 목록(5건)과 라벨(근거 있음/없음)
- 산출물: 평가 체크리스트
- 완료 기준: 가상 규정 텍스트 파일 3개(.txt) 작성 완료 및 요구 기준 충족 검증

### 2. 2단계 · RAG 파이프라인 설계 및 구현

- 목표: 문서 분할·임베딩·벡터 인덱싱·검색·LLM 호출을 포함한 최소 동작 RAG 파이프라인을 구현한다. 검색 결과에 근거(문서 ID·절차)를 포함하도록 설계한다.
- 기간: 3 · 시간: 9시간 · 비용: 0원
- 활동: 로컬 환경 구성: Python, 가상환경, 필요한 패키지 설치(예: sentence-transformers, FAISS 또는 ChromaDB, OpenAI/로컬 LLM 클라이언트)
- 활동: 문서 분할 전략(문단/절 단위) 적용 및 임베딩 생성
- 활동: 벡터 인덱스 생성 및 검색 함수 구현(상위 k개 결과 반환)
- 활동: 검색 결과를 프롬프트에 포함시켜 LLM 호출(간단한 프롬프트 템플릿) 및 응답 생성
- 활동: 응답에 근거(문서 ID·절차)를 포함하도록 포맷 설계
- 산출물: 실행 가능한 코드 저장소(README 포함)
- 산출물: 샘플 실행 스크립트(질문 입력 → 검색 결과 + LLM 응답 출력)
- 산출물: 샘플 응답 5건(각 응답에 근거 표시 포함)
- 완료 기준: 실행 가능한 코드 저장소(README 포함) 작성 완료 및 요구 기준 충족 검증

- 목표: RAG 출력에서 근거가 있는지 판별하는 간단한 분류(예: 검색 점수 임계값·메타데이터 확인)를 추가하고, 5개 질문을 대상으로 정량적·정성적 평가를 수행한다.

- 활동: 5개 질문을 실행하여 결과 수집(정답 여부, 근거 표시, 분류 결과)
