## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

비용 우선의 2주 실습형 로드맵 — 동시성 오류 재현 및 잠금 적용 비교

가용 시간(총 6시간)과 예산(0원)을 고려해 로컬 환경에서 최소한의 코드·실험으로 동시성 결함을 재현하고, 잠금 적용 전후의 로그를 비교해 원인과 효과를 문서화한다. 외부 유료 서비스나 추가 기간은 사용하지 않는다.

### 1. 환경 준비 및 재현 코드 작성

- 목표: 로컬에서 재현 가능한 최소 코드(스레드 2개, 공유 카운터)를 작성하고 데이터 레이스를 관찰할 수 있는 로그를 확보한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 개발 환경 확인(예: Linux/macOS/WSL, C/C++ 컴파일러 또는 Python 설치).
- 활동: 간단한 프로그램 작성: 두 스레드가 공유 카운터를 N회 증가시키는 코드(예: C의 pthreads 또는 Python의 threading).
- 활동: 동시성 오류 재현을 위한 반복 실행 스크립트 작성(예: 100회 반복 실행 후 결과 수집).
- 활동: 로그 포맷 정의: 각 실행의 최종 카운터 값과 예상값(예: 2*N)을 기록.
- 산출물: 소스 코드 파일(예: race_example.c 또는 race_example.py)
- 산출물: 실행 스크립트(반복 실행 및 로그 수집)
- 산출물: 초기 실행 로그(잠금 미적용) 샘플 파일
- 완료 기준: 미확인

### 2. 잠금 적용 및 비교 분석

- 목표: mutex(또는 동등한 동기화 기법) 적용 전후의 로그를 비교해 동시성 문제의 원인·해결 효과를 문서화한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 잠금 적용: 공유 카운터 접근을 보호하는 mutex 또는 lock을 코드에 추가.
- 활동: 동일한 반복 실행 스크립트로 잠금 적용 전후의 로그를 수집(각각 100회 이상 권장).
- 활동: 로그 비교: 잠금 미적용 시의 불일치(예: 최종 카운터 < 2*N)와 잠금 적용 시의 일관성(예: 최종 카운터 == 2*N)을 수치로 정리.
- 활동: 간단한 분석 보고서 작성: 재현 방법, 로그 예시, 원인(데이터 레이스)과 해결(뮤텍스)의 효과, 한계(성능 영향 등) 기술.
- 산출물: 잠금 적용된 소스 코드 파일(예: race_example_mutex.c 또는 race_example_mutex.py)
- 산출물: 잠금 적용 전후의 로그 파일(각각)
- 산출물: 비교 분석 보고서(최대 1~2페이지): 재현 절차, 로그 예시, 결론 및 한계
- 완료 기준: 미확인
