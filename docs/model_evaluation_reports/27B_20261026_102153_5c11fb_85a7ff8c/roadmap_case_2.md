- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 시간 우선
- 기간: 8주 · 주당 3시간 · 예산 20000원

## 계획

1주 집중: SQLite 기반 최소 재고 DB 설계·검증

주어진 1주(총 4시간) 내에 로컬 SQLite에서 동작하는 최소 재고 데이터 모델(품목·입출고)을 설계하고, 외래키 제약과 JOIN 결과를 검증하는 SQL 스크립트와 간단한 검증 결과를 산출한다. 시간 우선 관점으로 설계 범위를 최소화하여 설계→구현→검증을 완료한다.

### 1. 요구·모델 정의 및 스키마 구현

- 목표: 핵심 엔티티(품목, 입출고)와 최소 속성·제약(외래키 포함)을 정의하고 SQLite 스키마를 작성한다.
- 기간: 0.33 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 목표 범위를 2개 테이블(품목: id, name, unit, initial_stock; 입출고: id, item_id, type(IN/OUT), qty, occurred_at)로 축소
- 활동: SQLite용 CREATE TABLE 스크립트 작성(외래키 제약 포함, PRAGMA foreign_keys=ON 명시)
- 활동: 간단한 ER 다이어그램(텍스트 표기)과 각 컬럼의 목적을 README에 기록
- 산출물: schema.sql (SQLite CREATE TABLE 문 포함)
- 산출물: README.md (엔티티·속성·외래키 설명, 사용 방법)
- 완료 기준: schema.sql을 실행하여 SQLite DB 파일이 생성되고, 외래키 제약이 활성화된 상태에서 테이블이 정상 생성되는 것을 확인한다.

### 2. 샘플 데이터 적재 및 JOIN·제약 검증

- 목표: 샘플 데이터를 삽입하여 외래키 제약이 동작함을 확인하고, JOIN 쿼리로 입출고 합계·재고 잔량을 검증한다.
- 기간: 0.33 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 샘플 데이터 삽입 스크립트(data.sql) 작성(품목 3개, 입출고 이벤트 6개 권장)
- 활동: 외래키 위반 테스트(의도적으로 잘못된 item_id 삽입 시도)로 제약 동작 확인
- 활동: JOIN 쿼리 작성: 품목별 현재 재고 계산(초기 재고 + IN - OUT), 검증용 기대값과 비교
- 산출물: data.sql (샘플 INSERT 문)
- 산출물: verify.sql (JOIN 쿼리와 기대 결과 비교를 위한 간단 체크 쿼리)
- 산출물: verify_results.txt (쿼리 실행 결과 스냅샷 및 간단한 비교 설명)
- 완료 기준: data.sql을 적용한 후 verify.sql의 JOIN 쿼리 결과가 README에 명시한 기대값과 일치하고, 외래키 위반 시 삽입이 실패함을 확인한다.
