- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 시간 우선

## 계획

1주 집중: SQLite 재고 모델 설계·검증(시간 우선)

가용 시간(총 4시간)에 맞춰 목표 범위를 최소화하여 로컬 SQLite에서 재고 품목과 입출고 테이블을 설계하고, 외래키 제약과 JOIN 쿼리의 결과를 검증하는 산출물을 만든다. 설계→구현→검증의 최소 루프를 완료하는 것을 목표로 하며, 불필요한 확장(예: 클라우드 배포, 복잡한 정규화)은 배제한다.

### 1. 요구·스키마 설계

- 목표: items와 transactions의 최소 컬럼·타입·외래키를 정의하고 샘플 데이터(3~5개 품목, 6~10건 입출고)를 설계한다.
- 기간: 1.0 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 목표 범위를 재확인(로컬 SQLite, 단일 DB 파일)
- 활동: items 테이블 컬럼 정의: id INTEGER PK, name TEXT, initial_stock INTEGER
- 활동: transactions 테이블 컬럼 정의: id INTEGER PK, item_id INTEGER FK->items.id, qty INTEGER, tx_type TEXT('IN'/'OUT'), tx_date TEXT
- 활동: 샘플 데이터셋(테이블 형태)을 작성하여 검증 시나리오를 만든다.
- 산출물: 스키마 정의 파일(schema.sql) — CREATE TABLE 문 포함
- 산출물: 샘플 데이터 목록(sample_data.csv 또는 INSERT 문)
- 완료 기준: schema.sql과 샘플 데이터가 준비되어 로컬 SQLite에 적용할 준비가 되었음을 확인(파일 존재 및 문법 오류 없음).

### 2. SQLite 구현 및 쿼리 작성

- 목표: 로컬 SQLite 파일에 테이블을 생성하고 샘플 데이터를 삽입한 뒤, 외래키 제약이 동작함을 확인하고 JOIN으로 현재 재고 잔량을 계산하는 쿼리를 작성한다.
- 기간: 1.0 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 로컬 SQLite 환경 준비(예: sqlite3 CLI 또는 Python sqlite3 모듈)
- 활동: schema.sql 적용 및 sample_data 삽입
- 활동: 외래키 활성화 확인(예: PRAGMA foreign_keys=ON)
- 활동: JOIN 쿼리 작성: items LEFT JOIN transactions로 품목별 현재 재고 계산(초기 재고 + IN - OUT)
- 산출물: inventory.db (SQLite 파일) 또는 DB 생성 스크립트
- 산출물: queries.sql — JOIN 및 잔량 계산 쿼리 포함
- 완료 기준: queries.sql의 JOIN 쿼리를 실행했을 때 샘플 데이터에 대해 기대한 잔량 값이 반환됨(예: 각 품목에 대해 계산된 잔량이 샘플 시나리오와 일치).

### 3. 검증·결과 정리

- 목표: 외래키 위반 시 예외가 발생하는지, JOIN 결과가 설계한 기대값과 일치하는지 확인하고 간단한 검증 리포트를 작성한다.
- 기간: 1.0 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 외래키 위반 테스트: 존재하지 않는 item_id로 INSERT 시도하여 실패 확인
- 활동: JOIN 결과와 수동 계산(샘플 데이터 기반) 비교
- 활동: 간단한 README 또는 검증 리포트 작성(설계 의도, 테스트 케이스, 결과)
- 산출물: validation_report.md — 테스트 케이스와 결과(외래키 위반 예시, JOIN 결과 스냅샷)
- 산출물: 최종 산출물 목록(schema.sql, queries.sql, inventory.db 또는 생성 스크립트)
- 완료 기준: 외래키 위반이 의도대로 차단되고, JOIN 쿼리 결과가 수동 계산과 일치함을 문서로 증명함.
