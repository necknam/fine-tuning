# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 비용 우선
- 기간: 6주 · 주당 3시간 · 예산 20000원

## 계획

2주(총 6시간) 실습 중심 동시성 결함 재현 및 잠금 효과 검증

가용 시간(2주×3시간=총 6시간)과 비용(0원) 제약을 우선 반영해 목표 범위를 '로컬에서 스레드 두 개의 공유 카운터 레이스 컨디션 재현 → 간단한 동기화(뮤텍스) 적용 → 로그 비교로 효과 확인'으로 축소했습니다. 완성 서비스나 성능 최적화는 포함하지 않습니다. 각 단계는 실제 코드 실행과 로그 비교를 완료 기준으로 하며, 필요한 학습 자료는 제공된 K-MOOC 강좌의 관련 주차(프로세스/스레드, 동기화)를 참조합니다.

### 1. 환경 준비 및 재현 코드 작성

- 목표: 로컬에서 실행 가능한 최소 재현 코드(스레드 2개, 공유 카운터, 반복 실행 스크립트)를 작성하고 실행해 오류를 관찰한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 개발 언어 선택(예: C 또는 Python) 및 로컬 개발 환경 확인(컴파일러/인터프리터, 빌드 도구).
- 활동: 공유 변수(정수 카운터)를 두고 두 스레드가 N번씩 증가시키는 간단한 프로그램 작성(예: 각 스레드 100,000회 증가).
- 활동: 동시성 오류를 유발하기 위해 잠금 없이 실행하고, 결과를 10~20회 반복 실행해 로그(예: 최종 카운터 값)를 수집.
- 활동: 간단한 실행 스크립트(쉘 스크립트 또는 Python 스크립트)로 반복 실행 및 로그 수집 자동화.
- 산출물: 재현 코드 소스 파일(예: race_counter.c 또는 race_counter.py)
- 산출물: 반복 실행 스크립트(예: run_race.sh)
- 산출물: 잠금 미적용 상태의 실행 로그(최소 10회)와 요약(예: 기대값 대비 누락 횟수)
- 완료 기준: 잠금 미적용 상태에서 반복 실행 시 기대값(예: 200,000)과 실제 최종 카운터 값이 불일치하는 사례가 로그로 확인되어야 완료로 본다. (불일치 사례가 없으면 재현 조건을 조정해 재시도)
- 추천 자료 KMOOC_21162: 제공 근거에서 확인되지 않음

### 2. 동기화 적용 및 비교 검증

- 목표: 뮤텍스(또는 언어별 동등한 동기화 primitive)를 적용해 재현 코드를 수정하고, 잠금 적용 전후의 로그를 비교해 오류가 제거되었음을 확인한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 재현 코드에 뮤텍스(예: pthread_mutex_t 또는 Python threading.Lock)를 적용해 공유 카운터 증가를 보호.
- 활동: 동일한 반복 실행 스크립트로 잠금 적용 후 10~20회 실행해 로그 수집.
- 활동: 잠금 적용 전후의 로그를 비교(예: 기대값과 실제값의 차이, 실패 빈도)하고 간단한 표로 정리.
- 활동: 간단한 한계 분석: 동기화로 인한 성능 영향(예: 실행 시간 변화)을 측정하고 한계와 다음 학습 포인트를 기술.
- 산출물: 뮤텍스 적용된 코드 소스 파일
- 산출물: 잠금 적용 후 실행 로그(최소 10회) 및 전후 비교 표
- 산출물: 간단한 결과 요약(오류 제거 여부, 관찰된 성능 변화, 재현성·한계 설명)
- 완료 기준: 뮤텍스 적용 후 반복 실행에서 기대값과 실제값이 일치하는 사례가 로그로 확인되고, 전후 비교 문서가 제출되어야 완료로 본다. 성능 변화는 측정·기재하되 최적화 완료는 요구하지 않는다.
- 추천 자료 KMOOC_21162: 제공 근거에서 확인되지 않음
