02. 파인튜닝 데이터 — 왜 1,500건인가

일정상 학습·검증 시간을 줄이기 위해 총 1,500건으로 제한했습니다. 이 수량이 최적이라는 실험 결과가 나온 것은 아닙니다. 긴 입력이 많아 건수를 절반으로 줄인다고 실행 시간도 정확히 절반이 되는 것은 아닙니다.

어떻게 선별했는가

기존 3,000 − 범위 밖 400 + 시험 19 = 2,619→보류 455 · 유효 후보 2,164→기존 1,237 선별 + 부족 유형 263 보강→최종 1,500

형식·중복·근거·조건 위반을 로컬에서 검사하고 대표 답변을 검토했습니다. 7유형별 최소 60건을 확보한 뒤 나머지는 선별 우선순위에 따라 구성했습니다. 신규 263건의 작성 출처는 OpenAI 원문 180건, 에이전트 수정 7건, 에이전트 직접 작성 76건입니다. 직접 작성 답변도 실제 입력·DB 근거만 사용하며 없는 자료를 만들지 않습니다.

1,500건과 보고서용 10개는 다릅니다

학습 1,200검증 150평가 150

학습 1,200건·검증 150건·별도 평가 150건을 각각 전체 사용합니다. 별도 평가 정답은 학습에 넣지 않습니다. 보고서 공통 입력 10개는 이 1,500건과 별개이며 모든 비교 실험에 같은 입력을 사용합니다.

검증 범위와 한계

  • 1,500건의 형식·자료 ID·DB 근거·중복·프로젝트 family 분할·학습 마스크·토큰 길이를 검사했습니다. 양쪽 폴더 사본의 해시도 일치합니다.
  • 기존 대표 10건과 보강 대표 10건을 에이전트가 내용 검토했습니다. 전수 의미 검수와 사람의 전수 검수는 하지 않았습니다. 표본 결과를 전체 정확도로 볼 수 없습니다.
  • 프로젝트 family는 12개로 한정됩니다. 승인된 규정 인용의 긍정 사례도 부족해, 새로운 직무 전반과 규정 인용 품질은 별도 확인해야 합니다.
  • 최대 6,858토큰을 확인했고 설정 길이는 7,168입니다. 실제 GPU 메모리·속도 적합성은 아직 확인 전입니다.

03. 파인튜닝 과정 — 무엇을 실행하고 비교하는가

QLoRA는 기본 모델을 4비트로 불러오고 작은 추가 가중치인 어댑터를 학습하는 방식입니다. 이번에는 자료 자체를 외우게 하기보다, 제공된 근거와 제약에 맞게 답하는 행동을 학습시킵니다.

비교할 결과

같은 모델 revision·입력·생성 조건으로 원본 모델과 4·5 epoch 어댑터를 비교합니다. 형식 준수, 근거 밖 자료 추천, 시간·비용 조건, 부분 수정 보존, 근거 부족 대응을 확인합니다. 전체 LLM 유료 채점은 자동 실행하지 않습니다.

남은 작업 — 실행 순서

  1. RunPod 연결: Pod 실행 후 Jupyter 주소·인증을 확인하고 필요한 고정 데이터를 전달합니다.
  2. GPU 사전 점검: 메모리·속도를 측정해 전체 시간·비용을 산정합니다.
  3. 본 학습: 학습 1,200건 전체로 5 epoch를 실행하고 검증 150건을 확인합니다.
  4. 비교 평가: 원본과 4·5 epoch 어댑터를 별도 평가 150건 및 동일 공통 입력 10개로 비교합니다.
  5. 보고서 갱신: 실제 결과·오류·시간·비용을 이 보고서에 반영합니다.
  6. 서비스 연결: 검증한 어댑터를 연결해 생성·수정·저장을 확인합니다. OpenAI 우선, 파인튜닝 Qwen 차순위를 유지합니다.

별도 보완 과제는 IT 자료의 유효 근거 확대와 규정 검토입니다. 현재 학습 근거 스냅샷과 분할을 바꾸지 않고 관리합니다. 학습 후 두 앱의 최종 리뷰에서 모바일 반응형 개선 범위도 정합니다. 모바일 개선은 아직 구현하지 않았습니다.
