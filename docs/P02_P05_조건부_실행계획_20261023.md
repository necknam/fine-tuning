# 개선 v4 P02~P05 조건부 실행 계획

사용자 승인: 기존 데이터보다 개선되거나 비슷한 수준이면 현재 데이터로 P05까지 진행한다. 현재 진행 중인 P01을 재사용하며 기존 데이터와 P01을 다시 학습하지 않는다.

## 실행 조건

기존·개선 P01의2·5에포크를 동일 DB 근거·프로필·고정10개 입력 및 동일 생성 조건으로 비교한다. 형식 준수, 근거 정확성, 사용자 조건 준수, 수정 요청 보존, 보고서 실용성을 출력 내용으로 검토하고, 근거 조작·중요 조건 위반 등 중대한 오류도 별도 집계한다. 학습 손실만으로 진행 여부를 판정하지 않는다.

비슷하거나 나아진 결과이며 중대한 오류가 늘지 않을 때 P02~P05를 순서대로 실행한다. 판정 근거를 먼저 기록한다. 에이전트의 내용 검토는 실제 사용자 사람 점수와 구분하고 사람 평가란에 임의로 입력하지 않는다. 불명확하거나 조건 미달이면 추가 학습을 시작하지 않고 이유를 보고한다.

## 동일하게 유지하는 조건

개선 v4 전체1,500건,5에포크,저장·평가2·5에포크,같은 고정10개 DB 스냅샷,동일 seed42,최대길이10,240,BF16 LoRA,B200 고속 FLA/Triton3.6 환경을 유지한다. 기준 묶음 ID는 compare_saved_baseline_v4_full1500_fixed10_v1이며 새로운 DB 스냅샷을 만들지 않는다. 각 프리셋은 독립적인 실행 ID를 사용한다.

| 순서 | 프리셋 | P01에서 변경 | 설정 |
| --- | --- | --- | --- |
| 1 | P02 | 학습률5e-5 | configs/hyperparameters.reviewed_v4.P02.yaml |
| 2 | P03 | 학습률7.5e-5 | configs/hyperparameters.reviewed_v4.P03.yaml |
| 3 | P04 | 학습률1.5e-4 | configs/hyperparameters.reviewed_v4.P04.yaml |
| 4 | P05 | LoRA r16 / alpha32 | configs/hyperparameters.reviewed_v4.P05.yaml |

설정은 build_plans로 검증했으며 품질 판정 전 GPU 작업은 제출하지 않았다. 제어 계획은 Documents/Codex/conditional-p02-p05-plan.json 및 승인 Pod outputs/conditional_p02_p05/plan.json에 보존한다.

## 시간 예산

현재 실측23초/optimizer step과470스텝을 적용하면 프리셋 하나의 순수 학습은 약3시간이다. 최근21~25초 범위로는 약2시간45분~3시간16분이다. 기존 저장 가중치의20개 출력 기록은 답변당 약15~91초였으나 출력 길이·컴파일·새 런타임·실제 고정 입력이 달라 그대로 보장할 수 없다.

학습→2·5에포크각10개답변생성→저장·결과 검토를 포함한 한 프리셋의 임시 예산은3.5~4.5시간, 추가4개는14~18시간이다. 현재 진행 중인 P01의 남은 학습 및 최초 기존 가중치 비교는 이 추가4개 예산에 포함하지 않는다. 새 런타임의 실제 답변 생성이 끝나면 예산을 갱신한다.

## P05 완료 후 Pod 정지

사용자가 P05 완료 후 승인 Pod kq65qxmwibvy27의 STOP을 명시적으로 승인했다. 학습뿐 아니라2·5에포크 답변 생성·평가·최종 보고서 저장과 가중치/보고서의 원격 백업·검증, 필요한 GPU 작업 종료까지 확인한 뒤 정지를 시도한다. DELETE/Terminate/볼륨 삭제는 승인 범위가 아니다.

현재 기존 Pod 내부 키로 수행한 관리 API 사전 읽기 조회는 HTTP403으로 거부되어 자동 정지 가능 여부가 확정되지 않았다. 완료 시 기존 승인 인증으로 STOP을 시도하고 실제 관리 상태를 확인한다. 불가·실패·상태 확인 불가이면 사용자 지정 이메일로 수동 정지/확인이 필요하다고 알린다. 연결 끊김만으로 정지 성공을 보고하지 않는다. P05가 품질 조건 미달로 실행되지 않으면 이 완료 조건으로 자동 정지하지 않고 미실행 사유와 Pod 상태를 이메일로 안내한다.
