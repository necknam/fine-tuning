# 재시작과 중단 복구

## Streamlit 재실행

- 보고서·실행 설정·사람 점수·AI 점수는 Neon에서 복원합니다.
- Cloud Secrets에 RUNPOD_JUPYTER_URL과 RUNPOD_JUPYTER_TOKEN이 있으면 실행 현황에서 자동 재연결합니다.
- 연결 실패 시 60초 간격으로 재시도하며 마지막 저장 기록과 현재 연결 상태를 구분합니다.
- 수동으로 입력한 인증정보는 메모리에만 있습니다. 앱 프로세스를 다시 시작하면 재입력이 필요합니다.
- 재연결은 상태 조회만 수행합니다. GPU 학습이나 재학습을 자동 제출하지 않습니다.

## Streamlit을 닫아도 수집·AI 평가 유지

RunPod 연결 후 scripts/runpod_service.py를 비롯한 공통 모듈을 자동 배포하고 독립 CPU 프로세스를 시작합니다.
프로세스는 기존 RunPod 가상환경을 사용하며 GPU 모델을 로드하지 않습니다.
Neon/OpenAI 인증정보는 HTTPS 제어 세션을 거쳐 프로세스 환경에 전달하고 원격 파일에는 저장하지 않습니다.

- RunPod 파일 변화는 15초 간격으로 감지하고 보고서/실험 상태를 Neon에 저장합니다.
- 변화가 없으면 DB 확인 간격은 15분입니다. AI 평가 실패 후 수동 재시도를 요청하면 UI에서도 즉시 워커를 요청합니다.
- AI 평가 자동 실행 스위치를 끄면 독립 서비스의 신규 자동 요청도 멈춥니다. 이미 실행 중인 요청은 완료될 수 있습니다.
- 같은 서버의 서비스 중복 시작은 파일 잠금으로 막고, AI 작업은 Neon의 소유권 임대로 여러 서버 간 중복 실행을 막습니다.
- 서비스가 종료되면 열린 대시보드가 상태를 확인하여 다시 시작합니다.
- 로그에는 원시 예외나 비밀값을 기록하지 않습니다. 네트워크 장애는 지연을 늘려 재시도합니다.

## AI 평가 중단

- 완료한 입력/답변/평가 모델/평가 규칙이 일치하면 저장 결과를 재사용합니다.
- 작업 소유권은 10분 유효하며 실행 중 30초마다 갱신합니다.
- 기존 소유권이 살아 있으면 다른 워커가 작업을 가져가지 않습니다.
- 소유권 만료 후 새 워커가 중단된 RUNNING 항목을 PENDING으로 복구합니다.
- 소유권을 잃은 워커는 점수를 저장하거나 새 소유자의 상태를 변경할 수 없습니다.
- 일반 API 실패는 FAILED로 유지합니다. 실패 항목 재시도는 기존 명시적 버튼으로 요청합니다.
- API가 요청을 처리한 직후 DB 저장 전에 프로세스가 죽는 경우에는 재호출 비용이 발생할 수 있습니다. API와 DB를 하나의 트랜잭션으로 처리할 수 없으므로 비용의 정확히 한 번 처리는 보장하지 않습니다.

## Pod 재시작 또는 삭제

- Pod가 꺼지면 독립 프로세스도 꺼집니다. Pod 재가동 및 대시보드 재연결 후 서비스를 다시 시작합니다.
- 끊긴 GPU 학습은 기존 체크포인트가 있어야 이어갈 수 있습니다. 화면의 이어하기를 사용합니다.
- Pod/볼륨을 삭제하여 사라진 체크포인트는 이 복구 기능으로 되살릴 수 없습니다.
- Neon 기록과 HF에 업로드한 어댑터는 별도로 유지됩니다.

## 배포 상태

GitHub → Streamlit Community Cloud 배포에 사용하는 구조입니다.
로그인·권한 보호는 다음 단계입니다. 아직 Cloud 공개 배포는 하지 않았습니다.
현재 로컬 서버가 꺼져 있고 자동 연결용 Jupyter 설정이 없어 실제 Pod에 서비스 설치·장애 재현은 아직 확인하지 못했습니다.
다음에 대시보드를 실행하고 RunPod에 연결하면 자동으로 설치를 시도하며, 실패하면 화면에 표시합니다.
