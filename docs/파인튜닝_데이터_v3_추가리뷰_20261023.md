## 주요 문제와 권고

### 1. 비용 계산을 실제로 가르치는 정답이 부족함 — 우선 보완

로드맵 600건의 `total_cost_krw`가 전부 NULL이고, 단계 2,135개도 모두 비용이 NULL이다. 모르는 환경비를 추정하지 않는 것은 맞다. 그러나 확인된 강좌비·도서비의 소계와 미확인 환경비를 구분해 계산하는 사례도 없어, 비용 관점을 골라도 미확인으로만 답하는 편향을 학습할 위험이 있다.

권고: 전체 비용 확인 / 알려진 자료비 소계만 계산 가능 / 일부 비용 미확인 / 예산 초과를 구분한다. 실제 DB의 비용 근거를 사용하고, 없는 비용은 계속 NULL로 둔다. 무료 강좌라고 전체 실습비까지 무료라고 단정하지 않는다.

### 2. 승인된 규정으로 답하는 긍정 사례가 없음 — 우선 보완

1,500건 전체에서 입력의 승인 규정 청크가 0개이고, 정답의 규정 인용도 0개다. 근거가 부족할 때 보류하는 행동은 가르치지만, 적합한 승인 근거가 있을 때 근거 ID와 조건을 연결해 보고서를 쓰는 행동은 지도하지 못한다.

권고: 실제 승인·유효성·적용 범위가 확인된 근거가 있는 사례를 확보한 뒤 인용 정답을 만든다. 실제 DB에 적합한 승인 근거가 없다면 만들어 넣지 않고, 이 기능은 현재 데이터의 학습 범위 밖이라고 명시한다.

### 3. 진행 점검은 전부 미실행·미검증 — 우선 보완

60건 모두 `status=NOT_VERIFIED`, `completed=false`이고 입력도 계획서만 작성하고 실행하지 않았다는 사례다. 실행하지 않은 일을 완료라고 하지 않는 장점은 있지만, 충분한 실행 증거를 보고 완료 또는 부분 완료를 판단하는 학습이 없다.

권고: 합성임을 표시한 고정 실행 로그·기대값·실제값을 제공하고, 완료 / 부분 완료 / 테스트 실패 / 증거 부족 / 일정 지연을 구분한다. 합성 로그를 실제 직원의 실행 이력으로 표현해서는 안 된다.

### 4. 최신 제약과 배경의 시간 정보가 섞여 있음 — 정리 권고

로드맵 91건에서 배경 설명의 주당 시간과 최신 `constraints.weekly_hours`가 다르게 추출됐다. 예를 들어 all.jsonl 1행은 배경이 주 10시간, 최신 조건은 주 2시간이다. 최신 제약이 우선이라는 안내가 있으므로 이것만으로 논리 오류라고 단정할 수는 없다. 다만 일반 사례와 조건 변경 사례가 명확하게 구분되지 않아 불필요한 혼선을 준다. 탐지는 정규식 기준이며 모든 자연어 표현을 잡은 수치는 아니다.

권고: 일반 사례는 숫자를 통일하고, 시간 변경을 시험하는 사례는 변경 전·후와 사용자 변경 요청을 명확하게 기록한다.

### 5. 관점이 달라도 계획 자체의 변화는 약함 — 정리 권고

비용·시간·업무 적용이 각각 200건으로 균형을 이루지만, 생성 코드는 기존 계획에 관점별 공통 활동 문장을 추가하는 방식이다. 숫자 균형만으로 자료 선택·범위·우선순위가 관점에 따라 적절하게 달라진다고 볼 수 없다. 시간도 단계 주수에 주당 시간을 곱한 값이며 작업량을 독립적으로 추정한 결과는 아니다.

권고: 같은 목표·동일 자료에 대해 관점만 바꾼 대조 사례를 만들고, 실제 선택과 보류 이유가 달라지는지 검토한다. 시간 합계가 맞는 것과 계획이 현실적인 것은 별개로 평가한다.
