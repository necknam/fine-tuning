01. 무엇을 만들고 있는가

GrowPath는 개발·운영 직원이 자신의 조건에 맞는 AI 학습 계획을 세우고 수정하도록 돕는 서비스입니다. 이번 작업은 그중 로드맵 작성·수정 모델을 실험하고 평가하는 운영 도구입니다.

사내 시스템 개발 경험은 있지만 LLM·RAG 경험은 적은 직원을 주요 사례로 삼습니다. 비용·시간·업무 적용을 우선하는 관점과 기초 다지기 → 핵심 이해 → 업무 적용 → 성과 확인의 4단계를 반영합니다.

STEP 2 · 자동대기·실행우선순위와 등록 순서에 따라 한 작업씩 수행

Hugging Face는 학습 가중치 보관소, Neon은 실험·가중치 등록부입니다. 로컬 SQLite는 사람 평가 이력을 저장합니다. Jupyter 연결은 로컬에서 RunPod로 작업을 전달하는 통로입니다.

기획서의 서비스 DB와 이번 학습 운영용 Neon 등록부는 역할이 다릅니다. 이 작업으로 서비스 DB 이전이나 통합까지 수행한 것은 아닙니다.

03. 운영 도구에 구현한 기능

아래는 오늘 변경의 기반이 된 누적 구현 범위입니다. 이번 보고서는 이 대화에서 확인 가능한 GrowPath·qwen_factory 작업을 대상으로 합니다.

로컬 실험 제어

파라미터를 화면에서 수정하고 실험을 등록합니다. 내부 실행 설정은 자동으로 생성합니다.

직접 YAML을 편집하는 부담을 줄였습니다.

실험 대기열

실행 중 등록한 작업은 대기열에 들어갑니다. 우선순위를 조정하되 현재 작업을 중단하지 않습니다.

파라미터 조합을 순서대로 실험할 수 있습니다.

중단·재접속 기록

작업 상태와 로그, 마지막 동기화 기록을 로컬에 보관합니다. 기존 파일이 있는 실패·중단 실험을 이어가는 기능을 구현했습니다.

화면을 다시 열어 이전 진행 상황을 확인할 수 있습니다.

사람 평가

입력·모델 답변을 읽고 건별 1~5점을 저장합니다. 평가자별 기록과 재평가 이력을 보관합니다.

모델 품질은 사람이 판정하고, 답변 생성 성공과 구분합니다.

통합 보고서

실험 목록에서 보고서를 열고 입력별로 평가합니다. 평균이 v1_2.5(5점 만점) 형태의 제목에 반영됩니다.

많은 실험의 결과와 점수를 한곳에서 관리합니다.

설치·운영 문서

로컬과 GPU 서버 requirements를 두 개로 정리하고 새 Pod 연결, 인증, 데이터 위치, 복구 절차를 README에 통합했습니다.

다른 PC와 새 GPU 환경에서 재설정할 기준을 마련했습니다.

06. 사용자가 실제로 할 일

  1. 화면 실행 — 프로젝트에서 Streamlit을 실행하고 로컬 화면을 엽니다.
  2. 연결·인증 적용 — RunPod Jupyter 연결 후 HF·Neon 인증정보를 따로 적용합니다. 재시작 후 메모리의 인증정보는 다시 적용해야 합니다.
  3. 설정 선택 — P01 기준 또는 P00 커스텀을 고르고 파라미터를 수정합니다. 평가 입력 파일은 data/eval/prompts.jsonl을 선택하고 10개인지 확인합니다.
  4. 실험 등록 — 실행 중인 작업이 있으면 다음 순서에 들어갑니다. 현황에서 현재 단계·다음 단계·시간을 확인합니다.
  5. 보고서 평가 — 생성 완료 후 보고서를 열고 입력·답변을 비교해 1~5점을 저장합니다. 이름을 달리하면 복수 평가자가 평가할 수 있습니다.
보고서 이름 예시: v1_2.5(5점 만점)
평가한 입력들의 평균을 반영합니다. 미평가 입력이 남으면 현재 평균은 임시 평균입니다. “미평가 입력만 보기”를 켜면 이미 평가한 답변은 숨겨집니다.

평가 파일은 한 줄에 입력 한 건인 JSONL입니다. 정답은 없어도 됩니다. 파일만 늘리면 예전 보고서의 답변이 추가 생성되는 것은 아니며, 선택한 파일로 작업을 등록해야 합니다.

07. 남은 작업과 권장 순서

순서다음 작업완료 판단
1 · 최우선현재 Streamlit을 재시작해 새 화면을 확인하고 기존 실행 결과를 동기화합니다.가시성, 현재/다음 단계, 시간, 자동 갱신 제어가 실제 화면에서 정상 동작
2 · 통합 검증평가 입력 10개를 사용하는 제어 작업의 완료를 확인합니다.4·5에포크별 10건 답변과 보고서 수신, 평가 저장·재접속 확인
3 · 실제 데이터 준비실제 작성·수정 학습 데이터의 스키마·중복·분할·토큰 길이를 점검하고 샘플 전용 학습기의 제약을 해소합니다.평가 데이터가 학습에 섞이지 않고 실제 데이터 경로로 실행 가능
4 · 품질 비교고정 입력·검색 자료·생성 조건으로 기본 모델과 학습 모델을 비교하고 가능하면 검토자 2명이 평가합니다.평균 점수와 함께 자료 환각·시간/예산 위반·요청 밖 변경 건수를 기록
5 · 장기 운영대기열·중단 복구·새 Pod 설치를 실제 시나리오로 확인합니다.중복 학습 없이 복구하고 기록과 보고서를 지속 조회
아직 완료로 볼 수 없는 것
실제 데이터 학습 연결, 모델 품질 향상 입증, 최신 UI의 최종 시각 검증, 새 제어 흐름의 전체 완료 및 실제 장애 복구 시험입니다. 전체 GrowPath 서비스의 규정 RAG·진단·권한 기능도 이번 도구의 완료 범위에 포함되지 않습니다.

08. 언제 테스트를 끝내고 실전으로 넘어가는가

이번 실행에서 전체 흐름이 정상 동작하면 연결·운영 시험을 마무리하고, 실제 데이터 학습 준비로 넘어갑니다.

시험 종료 기준

  • 4·5에포크 각각 가중치 저장·업로드 완료
  • 에포크별 평가 입력 10개에 대한 답변 생성 완료
  • 로컬 보고서 수신 및 입력·답변 열람 가능
  • 입력별 1~5점 저장과 평균·제목 반영 확인
  • Streamlit 종료·재실행 후 기록과 평가 결과 재조회 가능

위 항목을 확인하면 연결·운영 시험은 완료로 판단합니다.

실제 학습으로 전환하는 순서

  1. 실제 작성·수정 데이터를 준비하고 학습·검증·평가 세트를 분리합니다. 중복과 토큰 길이를 점검합니다.
  2. 샘플 전용 학습기를 실제 데이터 경로와 설정에 연결합니다.
  3. 작은 규모로 실제 데이터 첫 실행을 확인한 뒤 본 학습을 진행합니다.
  4. 동일 평가 입력·검색 자료·생성 조건으로 기본 모델과 학습 모델을 비교하고 사람이 평가합니다.
시험 완료와 모델 품질 검증은 다릅니다.
샘플 실행 성공은 파이프라인이 작동한다는 뜻입니다. 실제 업무에 도움이 되는지는 실제 데이터와 고정 평가 세트로 확인해야 합니다. 현재 샘플 54개를 학습하는 상태에서 파라미터만 바꾸면 실제 데이터 학습으로 자동 전환되는 것은 아닙니다.

전환 후 사용자의 반복 작업: 파라미터 수정 → 실험 등록 → 자동 학습·답변 생성·보고서 수신 → 사람 평가 → 다음 실험 선택.

이 절차의 ‘실전’은 실제 데이터로 모델 실험을 운영하는 단계이며, GrowPath 서비스의 운영 배포 완료를 의미하지 않습니다.
