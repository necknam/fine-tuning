# B200 고속 커널 오류 수정 및 체크포인트 재개

2026-10-23. 사용자가 느린 우회 실행의 중단과 고속 커널 오류 수정을 지시하여 전환했다. 14:44 확인에서 체크포인트50 이후 실제61/470스텝까지 진행했다. 최근5개 실제 스텝 간격 중앙값21초, 우회 방식 약105초 대비 약5배 빨라졌다. 같은 시점 순수 학습 잔여 추정은 약2시간23분이며 가변 입력 길이·저장·답변 생성에 따라 달라진다. 학습과 최종 평가는 아직 완료 전이다.

재개 직후 tqdm의 s/it는 복원된50스텝까지 새로 처리한 것으로 계산하여 과소 추정한다. Cloud는 연속된 실제 스텝의 경과 시간 차이 중앙값에 남은 스텝 수를 곱하고, 첫 스텝의 컴파일 시간과 복원된 스텝은 처리 속도에서 제외한다.

## 원인과 변경

- Torch 2.8.0+cu128 / Triton 3.4.0 / B200에서 FLA GatedDeltaNet 역전파 컴파일 오류가 발생했다. 초기 PyTorch reference 우회는 최근 약105초/optimizer step으로 지나치게 느렸다.
- 기존 환경과 분리한 경로에 Triton 3.6.0을 설치하고 BF16 순전파·역전파 유한값 검사를 실행했다. 128·2,048토큰, 실제 모델과 같은48개 헤드의2,048·9,230토큰 검사를 모두 통과했다. 첫 실행 시간에는 컴파일·자동 튜닝과 동시 학습 영향이 포함되므로 이를 학습 속도로 사용하지 않는다.
- 새 RunPod 설치는 먼저 `python -m pip install -r requirements-runpod.txt`, 다음 `python -m pip install --no-deps -r requirements-kernel-b200.txt` 순서다. 두 파일을 한 번에 일반 의존성 해결기로 설치하면 Torch2.8의 Triton3.4 핀과 충돌하므로 분리했다. `pip check`의 해당 버전 충돌은 이 의도적인 오버라이드에 해당한다.
- 검증 후 venv에 Triton 3.6.0만 설치했다. Torch·Transformers·FLA 및 나머지 패키지는 유지했다. Torch의 기본 의존성 핀과 다른 조합을 실제 B200 검사로 검증한 것이며 임의의 다른 GPU·버전에서 지원을 보장하지 않는다.
- model_runtime은 검증된 Triton3.6에서 설치된 고속 FLA 커널을 선택하고, 요청한 정책과 실제 선택을 별도로 기록한다. Cloud 배포 묶음과 requirements도 함께 맞췄다.
