# Cloud 실험 작업 현황

2026-10-23 기준. 로컬 DB는 사용자가 관리하며 완료나 Cloud와 동일 상태로 간주하지 않는다.

## 데이터와 실험

- 최신 수정 후보: qwen_factory/data/production/curation_1500_reviewed_v4/release. all.jsonl 1,500건 전체 학습. 기존 분할 파일은 출처 보존용이며 이번 학습에서 제외하지 않는다.
- 실제 토크나이저 최대 9,230토큰. 학습 설정 10,240, 답변 생성 상한 4,096. 1,500건 모두 실제 encode_all 경로로 final_assistant_only 마스킹 검증 완료. 잘라내지 않는다.
- 개선 학습 설정: hyperparameters.compare.reviewed_v4_full1500.yaml. 5에포크 학습, 저장·비교는 2·5에포크. 이전 데이터는 RunPod outputs/B200_P01_epoch2 및 B200_P01_epoch5의 기존 가중치를 재사용하며 재학습하지 않는다.
- 고정 보고서 10개는 직원 ID [12,14,6,8,16,7,15,17,13,12]를 재사용한다. 첫 실전 평가 시 DB 근거와 프로필을 한 묶음으로 고정해 두 데이터 버전이 같은 입력을 사용한다.
- 새 직원 100명 전체를 무작위 재선택하면 비교 조건이 달라지므로 기존 고정10개 배정은 유지한다.
- 데이터 파일은 선택한 설정의 해시와 일치해야 한다. Cloud에 파일이 없으면 학습 all.jsonl 1,500건과 고정 입력 JSONL 두 개를 준비 화면에서 업로드한다.

## Supabase

- growpath_hr TEST_MANUAL 100명. 5개 부서 각 20명(부서장 1명+직원 19명). 기존9명 보존, 91명 추가.
- 100명 모두 사용자 지정 공통 테스트 비밀번호를 개별 솔트 Argon2id 해시로 저장·검증했다. 평문은 문서에 기록하지 않는다.
- 사번 NOT NULL·공백 금지·기관별 UNIQUE 적용. 직무·스킬·자격·학력은 기존 구조와 FK를 사용한다.
- 실제 팀원5명의 시트 정보는 아직 적재하지 않았다. 신규 가데이터와 비밀번호 변경은 Supabase에만 반영했다.
- Cloud가 독립 관리하는 계정이 있으면 구형 로컬→Cloud 덮어쓰기 도구는 중단한다.
- 읽기 전용 실험 계정은 TEST_MANUAL 프로필100명을 조회할 수 있지만 비밀번호 해시·이메일에는 접근하지 못한다.
- 직원 생성: database/scripts/seed_cloud_test_workforce.py. 비밀번호 재설정: database/scripts/set_cloud_test_passwords.py. 기본 실행은 미리보기, 실제 변경은 --apply.

## 검증 상태와 남은 작업

기존 공장 테스트71개를 실행했고 1개 건너뜀, 실패0이었다. 전체1500 학습 계약 검증을 추가해 다시 확인한다. 데이터 형식/합계/수정 보존 검사와 마스킹 검증은 통과했지만 실제 학습 효과를 의미하지 않는다. 프로젝트 가족12개 및 독립적인 전수 의미 검수 부재의 한계를 유지한다.

전체1500 설정의 Cloud 반영, B200 개선 학습의 실제 스텝 확인, 기존 저장 가중치와 개선 데이터의 2·5에포크 고정10 응답 비교 및 최종 평가가 남았다. RunPod가 꺼져 있는 동안 학습 또는 성능 검증 완료로 보고하지 않는다.

기존 실험은 BF16 LoRA, 1,500건, 최대 길이7,168이며 5에포크는 2에포크 이후 옵티마이저를 재시작한 3에포크 추가 학습이다. 개선 실험은 BF16 LoRA와 주요 하이퍼파라미터를 맞추되 긴 데이터를 보존하기 위해 최대 길이10,240, 연속5에포크를 사용한다. 데이터 효과만의 동일 조건 실험이라고 단정하지 않고 이 차이를 비교 보고서에 기록한다. B200의 Triton3.4/FLA 컴파일 실패는 Transformers의 명시적 PyTorch reference 선형 어텐션 설정으로 우회하고 실행 환경에 기록한다.
