# Dashboard Neon 저장소

2026-10-19: 로컬 평가 기록의 Neon 이전 및 활성화 완료.

## 저장 범위

- 기존 학습 테이블 `qf_runs`, `qf_artifacts`는 변경하지 않습니다.
- 대시보드는 별도 `qf_dashboard` 스키마를 사용합니다.
- `case_evaluations`: 사람 점수 이력. 기존 답변 서명 기반 유효성 유지.
- `ai_evaluations`: AI 점수, 근거, 사용 토큰. 사람 점수와 분리.
- `ai_queue`, `ai_worker_lease`: AI 대기열 및 중복 작업 방지용 임대.
- `documents`: 입력별 비교 보고서, 실행 설정, 등록 평가 입력 스냅샷, 버전 번호, 제어 이력.
- 보고서 Markdown과 요약은 저장된 기록으로 생성합니다. 가중치/학습 로그는 DB에 넣지 않습니다.

## 설정

현재 `.env`의 `DASHBOARD_STORAGE=neon`으로 명시적으로 선택합니다.
`DATABASE_URL`은 기존 Neon 연결을 사용합니다. 비밀값은 소스나 문서에 넣지 않습니다.
Neon 모드에서 연결이 실패하면 저장 실패를 표시하며 SQLite로 자동 전환하지 않습니다.
로컬 SQLite 사용 코드와 DB 파일은 제거했습니다. 대시보드는 Neon만 사용합니다. 이전 기록은 reports/backups/retired_sqlite_*.zip 압축 백업에만 보관합니다.

## 이전 및 검증

일회성 SQLite 이전 도구는 이전 완료 후 압축 백업으로 옮겼습니다. 이전 시 테이블과 허용된 문서만 추가했습니다.
기존 기본키는 덮어쓰지 않고, 항목별 일치를 확인합니다. 이미 사용 중인 Neon 기록을 덮어쓰는 동기화 도구가 아닙니다.
실행 중인 프로세스의 임대는 이전하지 않습니다.
`docs/neon_migration_verification.json`에 검증 건수와 용량이 있습니다.
백업은 `reports/backups/`에 보관합니다.

확인 사항: 사람 평가20건, AI평가40건, 대기열39건, 문서49개 원본 대조;
빈 디렉터리 문서 복원; PostgreSQL 큐 SQL/임대 트랜잭션 롤백;
기존 SQLite 자동 평가 큐와 API 모의 테스트 통과. 검증 과정에서 OpenAI 유료 호출은 하지 않았습니다.

## 이후 단계

이번 단계는 DB 저장 통합입니다. Cloud Secrets, RunPod와의 재연결/작업 재개,
Cloud와 독립적인 AI 작업 프로세스, 로그인/권한은 아직 별도 구현 단계입니다.
현재 AI 프로세스 실행 위치는 기존 로컬 방식이며 Cloud 영구 실행을 보장하지 않습니다.
Cloud 배포 전 지속 워커 및 복구 검증을 완료해야 합니다.

앱 시작 때 Neon 문서를 로컬 캐시로 복원합니다. 캐시 폴더를 영구 저장소로 취급하지 않습니다.
실제 데이터 학습은 여전히 별도 작업입니다. 지금은 기존 샘플 실험 기록의 저장소를 이전했습니다.
