# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 업무 적용 우선
- 기간: 4주 · 주당 3시간 · 예산 20000원

## 계획

2주(총 6시간) 실무 적용 중심 RDBMS 데이터 모델링 실습 로드맵

가용 시간(2주, 주 3시간, 총 6시간)과 예산(0원)을 반영해 목표 범위를 '가상 지점-지역 관계의 관계형 모델 설계 및 검증'으로 축소했습니다. GIS 서버 구축은 제외하고, 설계 산출물과 SQL 검증 스크립트를 만들어 실제 업무 적용 가능성을 확인하는 데 중점을 둡니다. 시간 제약으로 인해 심층 성능 튜닝이나 대규모 데이터 마이그레이션은 포함하지 않습니다.

### 1. 요구·데이터 정의 및 ER 설계

- 목표: 핵심 엔티티(지역, 지점)와 관계(지역-지점)를 정의하고 ER 다이어그램을 작성한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 업무 요구(지역별 지점 수 조회, 중복 지점 ID 방지)를 1페이지로 정리
- 활동: 필요 속성 목록 작성(예: region_id, region_name, branch_id, branch_name, region_id FK 등)
- 활동: 간단한 ER 다이어그램(엔티티·PK·FK 표기) 작성
- 활동: 검증 시나리오(중복 ID 삽입 시도, 지역별 집계 쿼리)를 정의
- 산출물: 요구사항 1페이지(검증 시나리오 포함)
- 산출물: ER 다이어그램(PNG 또는 PDF)
- 산출물: 검증 시나리오 목록
- 완료 기준: ER 다이어그램과 검증 시나리오가 작성되어, 검증 시나리오에 따라 실패/성공 케이스를 식별할 수 있어야 함.

### 2. 스키마 구현·검증 및 결과 문서화

- 목표: 설계한 스키마를 SQL DDL로 구현하고, 지역별 지점 수를 반환하는 SELECT와 중복 ID를 거부하는 제약 검증을 수행해 결과를 기록한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: DDL 작성: CREATE TABLE regions, CREATE TABLE branches(branches에 region_id FK 포함, branch_id UNIQUE/PK)
- 활동: 샘플 데이터 삽입(지역 3개, 각 지역에 2~3개 지점 등 소규모 데이터)
- 활동: 검증 쿼리 실행: 지역별 지점 수 집계(SELECT region_id, COUNT(*) FROM branches GROUP BY region_id)
- 활동: 중복 ID 거절 테스트: 동일한 branch_id 삽입 시도 및 제약 위반 확인
- 활동: 결과(쿼리 출력, 제약 위반 메시지)를 스크린샷 또는 텍스트로 기록
- 산출물: DDL 스크립트(.sql)
- 산출물: 샘플 데이터 삽입 스크립트(.sql)
- 산출물: 검증 쿼리 및 실행 결과(텍스트/스크린샷)
- 산출물: 간단한 검증 보고서(1페이지)
- 완료 기준: DDL과 검증 스크립트를 실행했을 때 지역별 지점 수 쿼리가 의도한 결과를 반환하고, 중복 ID 삽입 시 DB가 제약을 위반해 삽입을 거부하는 것이 문서로 확인되어야 함.
