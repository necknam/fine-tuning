# 맞춤형 학습 계획 보고서

## 프로젝트와 조건

- 목표: 가상 규정 3건에서 질문 5건의 근거를 표시하고 근거 없는 질문은 구분하는 최소 RAG 시제품
- 관점: 업무 적용 우선
- 기간: 4주 · 주당 3시간 · 예산 20000원

## 계획

2주 실습형 RDBMS 모델링 — 최소 가용시간에 맞춘 핵심 검증

총 2주(총 6시간) 동안 관계형 DB 모델링의 핵심 흐름(요구정의→ER 설계→DDL·샘플데이터→핵심 질의·중복제어 검증)을 완료합니다. 시간 제약(주 3시간) 때문에 범위를 '가상 지점-지역' 관계와 지역별 집계, 중복 ID 거절 시나리오로 좁혀 실제 SQL 실행과 결과 확인에 집중합니다. GIS 서버 구축·공간 인덱스·대용량 성능 튜닝은 제외합니다.

### 1. 요구·ER 설계 및 DDL 작성

- 목표: 핵심 엔티티(지역, 지점)와 관계(지역에 속한 지점)를 정의하고, 중복 ID를 방지할 제약조건을 포함한 DDL을 작성한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 업무 요구(지역별 지점 수 조회, 중복 지점 ID 거부)를 1~2문장으로 정리
- 활동: 간단한 ER 다이어그램(지역:1—N:지점)을 작성(도구: draw.io 또는 텍스트 표기)
- 활동: DDL 작성: regions(region_id PK, region_name), branches(branch_id PK, region_id FK, branch_name, created_at) 및 FK 제약 포함
- 활동: 중복 ID 거절 방식 결정: PK/UNIQUE 제약 또는 삽입 전 존재검증 트랜잭션 예시 중 하나 선택
- 산출물: 요구 1~2문장 요약(텍스트)
- 산출물: ER 다이어그램(이미지 또는 텍스트 표기)
- 산출물: DDL 스크립트(.sql) — regions/branches 테이블 및 제약 포함
- 완료 기준: 미확인
- 추천 자료 KMOOC_20252: 제공 근거에서 확인되지 않음

### 2. 샘플 데이터 적재·질의·중복 거절 검증

- 목표: 샘플 데이터를 적재하고 지역별 지점 수를 구하는 SQL을 실행해 결과를 확인하며, 중복 ID 삽입 시 제약조건으로 거부되는지 시나리오별로 검증한다.
- 기간: 1 · 시간: 미확인시간 · 비용: 미확인원
- 활동: 샘플 데이터(지역 3개, 각 지역에 지점 2~4개) CSV 또는 INSERT 스크립트 준비
- 활동: 로컬 SQLite 또는 무료 PostgreSQL/MySQL 로컬 인스턴스에 DDL 적용 및 데이터 적재
- 활동: 지역별 지점 수 질의 작성 및 실행: SELECT r.region_id, r.region_name, COUNT(b.branch_id) FROM regions r LEFT JOIN branches b ON r.region_id=b.region_id GROUP BY r.region_id, r.region_name;
- 활동: 중복 ID 삽입 시나리오 실행(동일 branch_id로 INSERT 시도) 및 실패 로그/에러 메시지 캡처
- 활동: 간단한 검증 체크리스트 작성(예: 기대 카운트 vs 실제 카운트, 중복 삽입 시 에러 발생 여부)
- 산출물: 샘플 데이터 파일(.csv) 또는 INSERT 스크립트
- 산출물: 실행 가능한 SQL 스크립트(DDL+데이터+질의)
- 산출물: 실행 결과 스크린샷 또는 쿼리 출력(지역별 지점 수 표)
- 산출물: 중복 삽입 시도 로그(에러 메시지 포함) 및 검증 체크리스트
- 완료 기준: 미확인
- 추천 자료 KMOOC_20920: 제공 근거에서 확인되지 않음
